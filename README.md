## 01. 三分钟启动

运行环境：**Python 3.10 或更新版本**。不需要 `pip install`，没有数据库、Node/npm 或前端构建流程。

```bash
# 进入解压后的项目目录（含 server.py 的文件夹）
python server.py
# 浏览器打开：http://127.0.0.1:8000/
```

Windows 也可在目录中双击 `start_windows.bat`，然后按窗口提示打开浏览器。修改启动端口：`PORT=8080 python server.py`（在 Windows CMD 用 `set PORT=8080`）。

主要入口：
- `/`：完整 Web 产品
- `/api/health`：后端状态与 LLM 模式
- `/api/diagnosis?mode=normal`：全部真实证据快照和推导指标
- `/api/diagnosis?mode=missing|conflict|stale|offline`：数据问题演示
- `POST /api/ask`：研究问题到证据路由（见下方）
- `POST /api/pe`：**手动情景**静态 PE 演算，不是实时估值

## 02. 产品为什么存在

**核心用户**：希望研究 A 股个股、但不愿阅读数十到上百页财报的个人研究者和初阶投资分析者。**核心问题**不是给用户一个「好 / 坏」总分，而是：

1. 看见方向相反的证据，例如收入小增但利润下降；
2. 能拆开异常项，例如大幅增长的经营现金流背后含财务公司影响；
3. 所有定量结论可点开，检验**原始字段、单位、期次、披露日期、计算方法**；
4. 碰到缺失、冲突、过期、断线等问题时，系统明确降级，不装作一切正常；
5. 研究问答只选择可解释证据，不让 LLM 自己编造业绩或行情数字。

### 真实操作主链路

**进入 600519 → 看同口径 KPI → 选择研究视角 → 打开证据详情 → 回到原始公告 → 继续提问 → 看需要补充哪些资料**。其中「2026H1 经营现金流 +438.84%」与「利润 -1.95%」是核心说明场景。

产品现有功能：
- 4 个核心指标卡，所有数据由元级字段计算或显示，并且可点回明细；
- 7 种研究视角（经营质量、财务趋势、估值、行情特征、行业位置、重要事件、风险）；
- 2025 vs 2026 半年**同比**、2024 vs 2025 全年**同比**的口径隔离图；
- 14 条「正面事实 / 负面事实 / 方向矛盾 / 管理层观点 / 待验证」证据卡（新增回购注销事实）；
- 证据详情抽屉：字段原值、名称、期间、单位、统计口径、来源页码、官方公告跳转；
- 研究问答：意图路由与证据关联及模板化的字段分析，不生成涨跌预测、买卖建议；
- 用户输入假设股价后计算 `情景价 / 2025FY EPS`，醒目标明**非市场行情**；
- 4 类异常演示：字段缺失、来源冲突、数据过期、接口失败；
- PC、手机布局适配；Dockerfile 与 Render 托管配置。

## 03. 确定性计算、来源与 AI 的职责

```text
原始公告（来源 URL / 披露日期 / 表格期次 / 页码 / 字段口径）
    ↓ 数据录入与元信息登记（离线公告快照）
字段库 data/filings.json
    ↓ Python Decimal 运算（不使用网页四舍五入后的亿元数）
计算与证据状态引擎 diagnostic.py
    ↓ 返回字段 ID、指标、完整证据链
前端可视化与钻取 static/
    ↑ 用户自然语言问题
意图路由 server.py：可选 LLM 只选择证据 ID；无 Key 时本地多意图规则路由
```

### AI 使用原则

- 当前安装包**默认不需要 API Key**，使用本地多意图规则把问句映射为已有证据，并由确定性模板给出有限的财务变化说明。**此模式不是 LLM 推理。**界面和 API 均明确标明「离线路由」，不假装离线规则就是云端大模型。
- 填入环境变量 `OPENAI_API_KEY` 后，后端可以调用 OpenAI 聊天模型**只完成语义意图到证据 ID 的选择**。提示词禁止模型计算财务数字或给投资建议；结果仅接受预登记证据 ID；无效或调用失败退回确定性规则。
- **所有数字和正文解释**来自原始字段、确定性公式和经过维护的证据模板。模型不会覆盖它们；LLM 输出不存在「新事实生成」权限。
- 不能保证 LLM 或规则路由选择的证据在所有自然语言问题上都是最相关的，保留可直接浏览全部证据的通路。
- **目前没有真实配置 API Key 的 LLM 在线验收记录**。提交者可自备密钥复测。无需配置密钥也可端到端完成整个离线主链路。

## 04. 四个真正的产品决策

**A. 同一会计期间比较**：2026H1 与 2025H1 比，2025FY 与 2024FY 比。不拿全年绝对额和半年度绝对额做增长率。`合同负债`是 2026-06-30 vs 2025-12-31 期末余额变化，不冠以「同比」。

**B. 解释「现金流大增」而非自动贴正面标签**：半年报原文写明财务公司因素，所以 +438.84% 是事实，**酒类消费回暖**不是已经得到验证的事实。

**C. 拒绝伪估值和假同行榜**：缺少已核验的证券市场股价/历史行情/同行统一样本，就留下「待验证」，提供后续如何核验。用户输入的情景价不会进入真实指标。

**D. 异常降级是链式的**：`h26_revenue` 一旦冲突，收入增长与由其推算的毛利率均不可用；现金流数据缺失只阻断现金流相关证据，全年年报独立来源仍可用。避免对异常一刀切，也避免静默回退。

## 06. 部署公网（必须在提交前完成）

一种可行流程（GitHub + Render；需候选人自己的账户）：

1. 在 GitHub 新建仓库，把本项目源文件（**不要把 zip 当唯一仓库文件**）提交到仓库。**不要上传含密钥的 .env**。
2. 打开 <https://dashboard.render.com/>，选择 **New → Web Service**，连接上面的 GitHub 仓库。
3. 选择 Python 服务，构建命令 `true`，启动命令 `python server.py`；环境变量 `HOST=0.0.0.0`，Render 提供 `PORT`。也可以使用项目自带 `render.yaml` / Dockerfile 部署。
4. 等部署完成，打开平台实际分配的 HTTPS 地址，**在无痕窗口**操作完整流程，核验 API 和公告外链。把真实地址写入提交系统。
5. 提交真实 GitHub 仓库地址；完成一次 60～180 秒录屏后再提交可选视频。

**说明**：这是部署指南，不代表本交付包已在线部署；平台配置与免费套餐政策可能变化，应以平台当时界面为准。

## 07. 已知边界和未做事项

- 仅诊断单只股票贵州茅台；非任意股票识别工具，无真正多股批量比较。
- 原始财报数据已核对并纳入静态快照，**不是**扶摇 / iFinD 实时 API 接入；没有自动抓取和自动刷新机制。
- 未接入证券历史 K 线、交易日历、成交量，因此不输出任何真实实时价格、20/60 日波动指标或实际 PE。
- 尚无同行可核对同期间样本，行业排名与估值分位数明确设为「待验证」。
- 2026 半年报未经审计；源头会计数据真实不代表它们能直接预测证券收益。
- 本项目为研究支持，不对投资行为提供指令、目标价、确定性预测或收益承诺。
- 未生成并提交真实线上链接、源代码仓库 URL 或演示视频，候选人需依照前节实际完成线上交付。
